## 🔮 Where Curiosity Meets Code

I'm a final year student who learns by building. Every project starts as a blank `index.html` and ends as something people can actually use. I don't reach for a framework first. I learn how the web really works, then decide what to add.

I turn:

- 🧩 Messy real-world workflows into clean, usable interfaces
- 🏌️ Club operations into a working management system (see **Health Maps** below)
- ☁️ Cloud services into simple, dependable backends
- 🌪️ "Where do I even start?" into a shipped project

## 🚀 Currently Building

**⛳ Health Maps** — a golf club management system, and my final year project. Plain HTML, CSS and vanilla JavaScript on the front, Supabase for data and auth, Cloudflare R2 for file storage.

## 🧙‍♂️ The Builder's Manifesto

[![](https://img.shields.io/badge/BUILDER-IN_PROGRESS-8A2BE2?style=for-the-badge)](#)

### ⚡ FUNDAMENTALS FIRST ⚡

Behind every polished website is a handful of simple ideas: structure, style, behaviour. I'd rather master those than memorise a framework's magic.

Every project begins with a question: *"What if I built it myself?"*

> "Frameworks come and go. The browser, the DOM and the fundamentals stay."

### 🌌 My Principles

1. **Understand Before Abstracting** - I learn how it works first, then decide what tool to add
2. **Ship Real Things** - Projects like Health Maps teach more than any tutorial
3. **Simple Beats Clever** - Readable code that works is better than clever code that confuses
4. **Learn in Public** - What I learn goes into a repo, not a notebook
5. **Keep Growing** - Final year is a checkpoint, not a finish line

#### FROM CURIOSITY → CLARITY → CAPABILITY → CREATION

This is not just what I do. This is how I'm learning to become.
